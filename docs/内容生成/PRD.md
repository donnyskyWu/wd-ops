## 1. 项目信息

### 1.1 原始需求复述

神鱼体育的内容管理系统已有"新增内容"表单页面，用户希望在点击"生成"按钮后进入 AI 内容生成页面，通过多轮对话与 AI Agent 交互，生成赛事方案内容（如胜平负分析、让球分析等），最终将生成内容回填至原内容编辑页面。

### 1.2 技术栈建议

- 前端：Vue 3 + Vite + Element Plus（与现有内容编辑页面技术栈保持一致）
- AI 接口：统一网关对接多模型（qwen / deepseek / GLM / Kimi）
- 状态管理：Pinia 或 Vuex（与项目现有方案一致）

### 1.3 产品目标

| 序号 | 目标 | 衡量指标 |
|------|------|----------|
| 1 | **提升内容生产效率** | AI 生成方案首次采纳率 ≥ 60%；单篇内容平均制作时长缩短 50% |
| 2 | **降低人工创作门槛** | 非专业作者可使用 AI 生成赛事方案内容，覆盖 ≥ 80% 的方案类型 |
| 3 | **沉淀用户偏好，持续提升生成质量** | 偏好总结使用率 ≥ 50%；连续使用 3 次以上的用户满意度 ≥ 85% |

### 1.4 API 调用原则

| 原则 | 说明 |
|------|------|
| **同步非流式调用** | AI 内容生成为同步 API 调用，不使用流式输出，等待生成完成后一次性返回完整内容 |
| **参数简化** | 调用接口仅需传递赛事名称（`match_name`）和作者名称（`author_name`），无需传递 ID |
| **每次必传** | 每次调用必须完整携带以下参数：<br>1. `context`：上下文参数（赛事名称、作者名称、方案类型、历史战绩、主播风格、产品定义说明）<br>2. `preference_summary`：历史用户偏好总结<br>3. `conversation_history`：上次及之前的全部对话内容 |

## 4. 交互流程

```
[用户处于内容编辑页面]
        │
        ├─ 填写表单基本信息（赛事、作者、方案类型等）
        │
        ├─ 点击「生成」按钮
        │
        ▼
[系统] 校验必填项 → 不通过 → 提示用户补全
        │
        ▼ (通过)
[打开 AI 内容生成页面]（抽屉/全屏模式）
        │
        ├─ 自动带入：赛事信息、作者、方案类型（只读）
        │
        ├─ [5s] 展示「历史对话偏好总结」面板 → 5s 后自动收起为标题栏
        │
        ├─ 用户补充输入：历史战绩、选择主播风格、填写产品定义说明
        │
        ▼
[用户在对话输入框中输入初始想法/要求，点击发送]
        │
        ▼
[系统] 将「赛事信息 + 作者 + 方案类型 + 历史战绩 + 主播风格 + 产品定义说明 + 用户输入 + 偏好总结」
      组装为 Prompt，调用选定 AI 模型
        │
        ▼ (loading 状态，≤ 30s)
[AI 生成方案] → 展示在对话区（Markdown 渲染）
        │
        ├─ 用户满意 → 点击「采纳」
        │     │
        │     ▼
        │   [系统] 将方案内容回填至内容编辑页正文 → 关闭 AI 生成页面
        │
        ├─ 用户不满意 → 在对话框输入修改意见 → 发送 → AI 重新生成/回复
        │     │
        │     ├─ 继续迭代...（最多 10 轮）
        │     │
        │     └─ 满意后点击「采纳」
        │
        └─ 用户想从头开始 → 点击「重新生成」→ 确认 → 清空对话 → 重新开始
        │
        └─ 用户放弃 → 点击「取消」→ 关闭 AI 页面 → 返回编辑页（数据保留）
```

## 5. 业务规则

### 5.1 多模型切换

| 规则 | 说明 |
|------|------|
| 可选模型 | qwen、deepseek、GLM、Kimi（模型列表支持后台配置） |
| 切换行为 | 切换模型时弹出确认弹窗："切换模型将清空当前对话记录，是否继续？" |
| 上下文保持 | 确认后清空对话区，但**保留**信息参数区的已填内容（赛事、作者、方案类型、历史战绩、主播风格、产品定义说明） |
| 默认模型 | 默认选择上次使用的模型；首次使用默认 qwen |

### 5.2 偏好总结逻辑

| 规则 | 说明 |
|------|------|
| 触发条件 | 进入 AI 生成页面时，查询当前用户最近一次成功完成的对话会话 |
| 生成方式 | 由后端/Agent 基于历史对话内容自动提取用户偏好关键词并生成总结文本 |
| **提取维度** | 偏好总结需从以下四个维度对历史对话进行提取和总结：<br>1. **语言风格**：如"简洁直接"、"专业严谨"、"通俗易懂"、"幽默风趣"等<br>2. **赛事预测方向**：如"偏好胜平负分析"、"倾向让球盘口"、"关注大小球"、"注重半全场"等<br>3. **字数偏好**：如"简短精炼（300 字内）"、"中等篇幅（500-800 字）"、"详细深入（1000 字以上）"等<br>4. **内容修改倾向**：如"喜欢增加数据对比"、"要求更激进的角度"、"偏好保守稳妥方案"、"强调风险提示"等 |
| **总结示例** | "上次对话中，您偏好**简洁直接**的语言风格，侧重**胜平负分析**方向，期望篇幅**中等（500-800 字）**，修改时倾向于**增加数据对比和风险提示**。" |
| **缺失维度处理** | 若某维度在历史对话中未体现（如首次使用或历史对话未涉及该维度），该维度显示"未设定"，用户可手动补充 |
| 展示行为 | 进入页面时以浮动面板形式展示，5 秒倒计时后自动收起为折叠标题栏 |
| 展开/收起 | 点击标题栏可切换展开/收起状态 |
| 编辑能力 | 展开状态下用户可直接编辑偏好总结文本，修改后的偏好将在本次对话中作为 Prompt 补充参数生效 |
| 关闭 | 面板右上角提供关闭按钮（×），点击后完全隐藏面板（本次会话不恢复） |
| 手动触发 | 信息参数区增加"偏好总结"快捷入口，用户可随时点击查看/修改 |

### 5.3 对话轮次限制

| 规则 | 说明 |
|------|------|
| 单轮定义 | 用户发送 1 条消息 + AI 回复 1 条方案 = 1 轮 |
| 上限 | 单次会话最多 10 轮 |
| 接近上限提示 | 第 9 轮时，AI 回复末尾附加提示："已达到 10/10 轮对话上限，如需要请重新生成" |
| 达到上限 | 第 10 轮结束后，输入框置灰并提示"已达对话上限，请采纳当前方案或重新生成" |
| 重置 | 点击"重新生成"后轮次计数归零 |

### 5.3.1 API 调用原则

| 原则 | 说明 |
|------|------|
| **调用方式** | **同步非流式调用**，不使用流式（SSE）输出 |
| **加载状态** | 调用期间前端展示 Loading 动画（如 typing indicator），等待完整返回后展示内容 |
| **超时时间** | 初始方案生成 30s，修改回复 15s；超时提示用户重试 |
| **每次必传** | 每次调用必须携带：<br>1. `context`（赛事名称、作者名称、方案类型等上下文参数）<br>2. `preference_summary`（历史用户偏好总结，无历史时可传空字符串）<br>3. `conversation_history`（历史对话内容数组，首次传空数组） |
| **参数简化** | 上下文仅需传递赛事名称（`match_name`）和作者名称（`author_name`），无需传递 ID |

### 5.4 对话内容格式

| 规则 | 说明 |
|------|------|
| 用户消息 | 纯文本展示，左对齐（或右对齐，遵循现有 IM 规范） |
| AI 消息 | 支持 Markdown 渲染：标题、段落、加粗、列表、表格、代码块 |
| 代码块 | 支持语法高亮，默认使用 markdown 语法 |
| 表格 | 赛事方案中可能包含数据对比表格，需完整渲染 |
| 消息标识 | 每条消息标注发送者身份（"AI 助手" / 用户头像+昵称） |
| 滚动行为 | 新消息到达时自动滚动至底部 |

### 5.5 采纳回填规则

| 规则 | 说明 |
|------|------|
| 回填内容 | AI 最新一条生成的方案内容（Markdown 格式） |
| 回填目标 | 内容编辑页的"正文"富文本区域 |
| 回填方式 | 将 Markdown 转换为富文本格式后写入；或直接写入 HTML |
| 已有内容处理 | 若原正文区域已有内容，弹出确认弹窗："将覆盖当前正文内容，是否继续？" |
| 失败处理 | 回填失败时提示用户，并提供手动复制按钮 |

### 5.6 权限与安全

| 规则 | 说明 |
|------|------|
| 接口鉴权 | 所有 AI 调用接口需携带用户 Token |
| 内容审核 | 生成内容需通过基础敏感词过滤后展示 |
| 限流 | 单用户每分钟最多发起 3 次 AI 生成请求 |
