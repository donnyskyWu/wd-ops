## 1. 产品背景与痛点

公司目前运营着覆盖**公众号、视频号、抖音、快手、小红书、服务号、企业微信、个人微信**等多平台的内容账号矩阵。运营团队以 **IP 组** 为基本管理单位，每个 IP 组包含运营人员、主播、手机设备、手机卡等资产。

当前管理面临以下核心问题：

| 痛点领域 | 具体表现 | 业务影响 |
|---------|---------|---------|
| **数据割裂** | 各平台数据无法统一对比，IP 组维度无法聚合 | 决策缺乏全局视角，跨平台复盘困难 |
| **效率低下** | 运营人员大量时间花在手工收集、整理数据 | 人效低，重复劳动占用创作时间 |
| **决策滞后** | 爆款和问题作品无法及时发现 | 错失复制机会，低质内容持续消耗资源 |
| **资产管理混乱** | 手机、手机卡、实名人、公司与账号关联关系缺乏系统化管理 | 账号风险失控，责任难以追溯 |
| **财务核算不准** | 账号购买成本与过程成本无法精确归因到 IP 组和人员 | ROI 失真，绩效考核缺乏数据支撑 |
| **内容生产非标** | 创作依赖个人经验，审核不规范，优秀经验无法沉淀 | 合规风险高，规模化生产困难 |

**不做此平台的后果**：运营效率持续低下，财务核算不准确，爆款无法快速复制，低质内容无法及时优化，竞品动态无法系统监控，内容生产无法标准化和规模化，资产（手机/卡/实名人）管理混乱导致账号风险失控。

## 2. 产品定位与价值主张

### 2.1 产品定位

**聚合多平台数据的智能化运营分析平台**，以 **IP 组** 为管理核心，打通「账号资产 → 数据采集 → 运营分析 → 内容生产 → 财务核算 → 绩效激励」的完整运营数据闭环。

### 2.2 价值主张

| 价值维度 | 一句话描述 |
|---------|-----------|
| **统一视图** | 一个平台看全矩阵账号、粉丝、作品、财务与绩效 |
| **标准化生产** | SOP 流程 + 任务推送 + AI 辅助 + 三级审核，让内容生产可管可控 |
| **数据驱动决策** | 爆款/低分自动识别、ROI 实时核算、8 张标准报表 + 自定义分析 |
| **资产可追溯** | 公司→实名人→手机→账号→IP 组全链路关联，风险可预警 |
| **绩效可量化** | 考核模板 + 自动算分，让贡献看得见 |

### 2.3 产品边界

**本期覆盖**：
- 11 个业务模块（首页、运营管理、内容生产、绩效核算、账号管理、财务管理、数据分析、作品监测、配置管理、系统管理、数据采集）
- 覆盖 8 大新媒体平台 + 企微/个微私域运营

**本期不覆盖**（Phase 2 / 非签收路径）：

| 能力 | 说明 |
|------|------|
| 外部 SSO / 钉钉 OAuth 独立登录 | Phase 2；本期通过 Football 管理端壳登录 |
| 独立 OPS 登录页（Standalone 非 Gate 默认路径） | 非生产签收路径，不作为客户验收主链路 |
| M10 全量采集调度运维与外部采集规模化 | Phase 2；菜单与配置边界存在，交付不承诺全量采集运维手册级能力 |
| 部分 P1 增强 | 以各模块功能表「优先级」列为准（如人效盘点增强、外部作品监测深度等） |

**本期交付验收侧重**：日常运营可脱离 Excel 主链路；内容 SOP→审核→发布可走通；ROI/成本可录入与查询；监测与报表可读已落库数据。

## 3. 业务目标

### 3.1 战略目标

1. **提升运营效率**：将日常数据收集、报表制作时间从「小时级」降至「分钟级」
2. **实现财务透明**：账号成本与营收可精确归集到 IP 组、账号、经办人
3. **加速内容迭代**：爆款发现延迟控制在 1 小时内，低分内容当日可见
4. **规范内容生产**：全链路 SOP 管理，三级审核保障合规
5. **激励绩效闭环**：内容产出、传播效果、营收贡献与绩效考核直接挂钩

### 3.2 分阶段目标

| 阶段 | 核心交付 | 业务验收标准 |
|------|---------|-------------|
| **一期（P0）** | 首页、运营管理、内容生产核心、账号管理、财务管理、数据分析核心报表、作品监测爆款/低分、系统管理 | 日常运营可完全脱离 Excel；ROI 可核算；内容可走通 SOP→审核→发布 |
| **二期（P1）** | 计划管理、人效盘点增强、外部作品监测、漏斗分析、大屏配置 | 竞品监控可用；绩效与营收数据深度联动 |

| 权限级别 | 可见范围 | 典型角色 |
|---------|---------|---------|
| 全部数据 | 全公司/全租户 | 系统管理员、运营管理者 |

| 本 IP 组 | 所属 IP 大组/小组 | 运营组长、本组运营人员 |
| 仅本人 | 个人相关数据 | 运营人员、主播/作者 |

## 5. 核心业务场景

### 场景一：晨会看板 — 快速掌握全局

**角色**：运营管理者、运营组长  
**场景描述**：每日晨会前，管理者打开首页仪表盘，按 IP 组筛选查看核心指标（作者数、内容数、SOP 完成率、绩效等级），浏览内容发布趋势和平台分布，处理待办提醒（待审核内容、逾期任务、账号预警）。  
**业务价值**：5 分钟内掌握全局运营状态，无需翻阅多个平台后台。

### 场景二：账号资产建档 — 理清家底

**角色**：系统管理员、运营管理者  
**场景描述**：新 IP 组上线前，依次创建公司主体、IP 大组/小组、配置手机卡与手机设备、登记实名人、创建各平台账号并关联到 IP 组，最后配置微信-视频号-企微三方关联。  
**业务价值**：账号资产全链路可追溯，封号/认证到期可预警，公众号容量可管控。

### 场景三：标准化内容生产 — 从计划到发布

**角色**：运营管理者、运营组长、内容创作者、审核人员  
**场景描述**：管理者创建内容计划并下发任务（绑定 SOP 模板）；创作者接收任务，使用 AI 辅助创作内容；提交后经历初审→复审→终审三级审核；审核通过后自动发布；发布后数据采集获取效果数据。  
**业务价值**：内容生产流程标准化，合规风险可控，并行节点提升产出效率。

### 场景四：爆款复制与低分优化

**角色**：运营组长、数据分析师、运营人员  
**场景描述**：系统自动根据阈值规则识别爆款和低分作品；运营人员查看爆款列表分析传播特征，指导后续创作；低分作品触发优化提醒，组长安排复盘改进。  
**业务价值**：爆款发现延迟 ≤ 1 小时，低分内容当日可见，加速内容迭代。

### 场景五：财务 ROI 核算 — 算清账

**角色**：财务人员、运营管理者  
**场景描述**：财务人员录入账号购买成本和过程成本（租赁、投流、认证等）；系统按账号→IP 组归集成本；结合订单采集同步的营收数据计算 ROI；生成 ROI 分析报表供管理层决策。  
**业务价值**：每个 IP 组/账号的投资回报清晰可见，支撑资源调配决策。

### 场景六：绩效考核 — 激励闭环

**角色**：运营组长、运营管理者、全体被考核人员  
**场景描述**：组长按岗位考核模板发起月度考核；系统自动拉取指标数据（内容产出、SOP 完成率、ROI 等）并算分；组长可人工微调；结果归档并支持趋势分析。  
**业务价值**：绩效与业务数据直接挂钩，减少主观评价，激励导向明确。

### 场景七：竞品监测 — 知己知彼

**角色**：数据分析师、运营管理者  
**场景描述**：配置外部竞品账号采集；按 IP 主题/行业维度查看竞品动态；分析竞品爆款和低分内容特征；为内部创作提供参考。  
**业务价值**：竞品动态系统监控，创作策略有数据支撑。

### 场景八：自定义分析 — 灵活洞察

**角色**：数据分析师、运营管理者  
**场景描述**：分析师通过自定义查询工具，选择数据源、字段、过滤条件，生成列表或图表视图；满意后保存为模板；系统管理员可将查询发布给其他角色直接使用。  
**业务价值**：降低重复分析成本，业务人员可自助获取洞察。

## 6. 功能模块与业务价值

平台共 **11 个业务模块、34 个子功能**，按业务域组织如下。

### M0 · 首页仪表盘

| 功能 | 业务价值 | 优先级 |
|------|---------|--------|
| 首页仪表盘（含 IP 组筛选） | 一屏掌握核心运营指标、趋势、待办，支持按 IP 组下钻 | P0 |

**核心展示**：总作者数、内容总数、SOP 完成率、平均绩效等级、内容发布趋势、平台分布、待办提醒、快捷入口。

### M1 · 运营管理

运营管理中枢，围绕 IP 组串联日常运营数据视图。

| 功能 | 业务价值 | 优先级 |
|------|---------|--------|
| IP 组管理（大组/小组） | 建立两级 IP 组织架构，是全部业务的组织锚点 | P0 |
| 作者管理（主推号、运营→主播关联） | 管理内容创作者，关联主推号，明确运营对主播的管理关系 | P0 |
| 账号分析 | 按平台查看账号列表，下钻粉丝/作品详情 | P0 |
| 粉丝分析 | 粉丝增长、画像、LTV 分析 | P0 |
| 作品分析 | 作品传播效果、互动数据分析 | P0 |
| 内部内容分析（含数据补录） | 查看自有内容表现；接口异常时可手工补录缺失数据 | P0 |
| 人效盘点 | 按经办人统计任务完成率、内容产出、ROI 表现 | P1 |

**组织模型**：大组管理多个小组，大组不直接管理账号和主播，必须通过小组。

### M2 · 内容生产

实现内容从计划、创作、审核到发布的标准化全流程；v9.2 新增 IP 组长日任务登记、Football 发布方案玩法对齐、AI 排版与一键排版能力。

| 功能 | 业务价值 | 优先级 |
|------|---------|--------|
| SOP 管理 | 自定义标准作业流程，支持并行节点和审核节点；预置 14 节点标准内容生产流程；营销计划与启用 SOP 1:1 绑定 | P0 |
| 计划管理 | 制定内容运营计划，关联多 IP 组、SOP 模板与外部赛事，启动后自动生成任务 | P0 |
| 任务管理 | 基于 SOP 创建和分配任务，跟踪任务状态；支持工作说明与内容审核完成门禁 | P0 |
| **工作任务管理** | IP 组长按日登记「多赛事 × 作者 × 营销计划」；确认后按 SOP 全节点生成任务；矩阵视图纵览分布；赛后 AI 判定红黑 | P0 |
| 内容管理（玩法 + AI + 审核 + 发布） | 对齐 Football 发布方案（N 场 + 竞彩玩法）；jingcai AI 首生成/润色；三级审核；Football 双写 | P0 |
| **AI 排版 / 一键排版** | LLM 语义分段排版（不改一字）或四套 football-layout 预设一键套用；正文保真 | P0 |
| 公推模板库 | 公众号版式模板 CRUD、导入与套用，统一样式风格 | P0 |
| 内容知识库 | 沉淀优秀案例与运营经验 | P1 |

**预置 SOP 亮点**：标准内容生产运营流程包含 14 个节点、4 路并行（推文/方案/视频/直播可同步推进），最终汇聚到服务号推送和客户跟进。

**v9.2 增量亮点**：
- **工作任务**：组长确认登记即发布，内容生成节点自动建草稿并异步 AI 首写
- **玩法对齐**：OPS 与 Football 发布方案同构，一次编辑双端同步
- **AI 双路径**：文案走 jingcai，排版走 M8 LLM 或规则预设，职责分离

### M5 · 财务管理

精确核算账号投入产出。

| 功能 | 业务价值 | 优先级 |
|------|---------|--------|

## 7. 关键业务流程

### 7.1 基础数据初始化

新 IP 组或新账号上线时，按以下顺序完成资产建档：

```
创建公司 → 创建 IP 大组 → 创建 IP 小组
    → 配置手机卡 → 配置手机设备 → 配置实名人
    → 配置平台账号 → 关联到 IP 组/实名人/公司/手机
    → 配置个人账号（企微/个微） → 配置三方关联
```

### 7.2 内容生产全流程

```
运营管理者创建计划 → 创建任务（选择 SOP）
    → SOP 节点实例化（支持并行执行）
    → 创作者接收任务 → AI 辅助创作 → 提交内容
    → 初审 → 复审 → 终审（任一驳回则退回修改）
    → 发布内容 → 数据采集获取效果
    → 爆款/低分判定 → 绩效核算
```

### 7.3 运营分析全流程

```
数据采集完成 → 营收数据同步 + 成本数据同步
    → ROI 计算 → 更新运营指标
    → 阈值检测 → 触发则发送预警通知
    → 更新数据缓存 → 大屏/报表可用
    → 用户处理预警 → 财务成本归集 → ROI 分析报表
```

### 7.4 财务核算全流程

```
录入购买成本 → 录入过程成本 → 成本归集到账号
    → 成本归集到 IP 组 → 订单采集同步营收
    → 营收归集到账号/IP 组 → ROI 计算
    → 财务报表生成 → 审计日志记录
```

### 7.5 跨模块价值链路

| 业务链路 | 涉及模块 | 业务闭环 |
|---------|---------|---------|
| 数据采集 → 分析 → 决策 | M10 → M6 → M0/M7 | 数据新鲜 → 指标可见 → 行动决策 |
| 内容创作 → 审核 → 效果 → 绩效 | M2 → M7 → M3 | 生产 → 传播 → 评价 → 激励 |
| 资产建档 → 成本 → ROI | M4 → M5 → M6 | 投入可追溯 → 产出可核算 |
| 爆款发现 → 分析 → 复制 | M7 → M1 → M2 | 发现 → 分析 → 再创作 |

## 8. 核心业务规则

### 8.1 财务与核算规则

| 规则 | 说明 |
|------|------|
| ROI 计算 | ROI = 总营收 ÷ 总成本 |
| 账号成本分摊 | 支持按 IP 组、账号类型、成本类型分摊统计 |
| 购买成本 vs 过程成本 | 购买成本为一次性投入；过程成本为运营过程中多条记录（租赁、投流、认证等） |
| 财务审计 | 每次成本修改自动记录操作人和时间 |

### 8.2 内容生产规则

| 规则 | 说明 |
|------|------|
| 三级审核 | 初审 → 复审 → 终审，串行执行；任一环节驳回则流程结束，需修改后重新提交 |
| SOP 并行执行 | 同并行组的节点可同时推进，汇聚节点需等待所有前置节点完成 |
| SOP 审核 | 需审核的节点通过后，才触发后续节点 |
| AI 辅助创作 | 文案默认走 jingcai AI；排版走 AI 排版或一键排版；生成内容须经人工审核后方可发布 |
| 工作任务登记 | IP 组长确认登记后按营销计划解析 SOP 全节点生成任务；可撤回 |
| 玩法 SSOT | 内容 `matchScheme` 与 Football 发布方案同构，保存时双写 |

### 8.3 监测与预警规则

| 规则 | 说明 |
|------|------|
| 爆款判定 | 阅读量、点赞、评论、转发**同时**达到阈值（AND 关系） |
| 低分判定 | 阅读量、点赞、评论、转发**同时**低于阈值（AND 关系） |
| 账号异常预警 | 认证到期、封禁提醒、状态异常等，支持规则配置和通知 |
| 公众号容量预警 | 剩余可注册数低于阈值时预警 |

### 8.4 组织与权限规则

| 规则 | 说明 |
|------|------|
| IP 组层级 | 大组管理小组，大组不直接管理账号和主播 |
| 运营→主播关联 | 一个运营可负责多个主播，按 IP 组归类 |
| 数据权限 | 按角色 + 部门 + IP 组 + 人员四级过滤 |
| 主推号 | 每个作者关联一个主推公众号 |
| 三方关联 | 微信、视频号、企业微信的绑定关系在账号建档时配置维护 |

### 8.5 数据分析规则

| 规则 | 说明 |
|------|------|
| 自定义查询发布 | 系统管理员可将查询配置发布给其他角色直接使用 |
| 大屏数据 | 进入页面时加载数据，不自动轮询，支持手动刷新 |
| 粉丝 LTV | 平均粉丝生命周期 = 平均（取消关注时间 − 关注时间） |

| 指标 | 目标值 | 衡量方式 |

### 9.4 绩效指标

| 指标 | 目标值 | 衡量方式 |

### 9.5 用户体验指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|---------|

| 报表导出 | 10 万行 < 30 秒 | 导出性能测试 |
| 系统可用性 | ≥ 99.5% | 运维监控 |

## 13. M2 v9.2 增量需求与验收标准（摘要）

### 13.1 计划管理（FR-M2-009 / PROD-002）

**描述**：业务计划关联 SOP、一个或多个 IP 组与外部赛事；草稿期任务不可见；启动后进入「我的任务」；多 IP 组按组并行生成任务。

| AC 编号 | 验收要点 |
|---------|----------|
| AC-M2-009-1 | 保存草稿后任务列表不可见该计划任务 |
| AC-M2-009-2 | 启动后任务可见且状态为待执行（PENDING） |
| AC-M2-009-3 | 终止须组长审批通过后计划与任务均为已终止 |
| AC-M2-009-4 | 步骤分配赛事后，任务关联赛事属于步骤赛事集合 |
| AC-M2-009-5 | 仅草稿计划可编辑名称/日期/赛事池/步骤 |
| AC-M2-009-6 | 一步骤 2 赛事 + 1 执行人 → 生成 2 条任务 |
| AC-M2-009-7 | 计划详情展示任务列表及计划起止时间 |
| AC-M2-009-8 | 多 IP 组启动后各组均生成对应任务 |

**与工作任务边界**：计划管理由运营管理者驱动完整 SOP DAG；工作任务由 IP 组长按日登记「作者 × 营销计划 × 多赛事」，确认即发布。

### 13.2 工作任务管理（FR-M2-010 / PROD-006）

| 子需求 | 要点 |
|--------|------|
| FR-M2-010-1 | 任务登记 Tab：默认 10 行；多赛事/作者/营销计划；DRAFT 保存不生成 task |
| FR-M2-010-2 | 矩阵 Tab：列头含作者、IP 组、组长 |
| FR-M2-010-3 | 撤回：sheet 回 DRAFT；关联 task 取消且列表不可见 |
| FR-M2-010-4 | 赛后红黑判定：定时任务 + AI 预测对比赛果 |
| FR-M2-010-5 | 确认后自动内容草稿 + 异步 jingcai 首写 |
| FR-M2-010-6 | 确认后提醒执行人（站内 + 钉钉） |

**任务生成规则**：不创建内容计划；按营销计划解析启用 SOP，每个 SOP 节点 1 条 task；执行人按节点岗位在 IP 组内解析；同一工作日内同一作者下赛事 ID 不可跨行重复。

**完成门禁**：非内容生成节点须填写工作说明；内容生成节点须关联内容审核通过后方可完成节点。

### 13.3 amphipoda 玩法对齐（FR-M2-011）

| 子需求 | 要点 |
|--------|------|
| FR-M2-011-1 | 玩法 UI：竞足/传足/北单/足球 Tab；N 场 + 玩法 |
| FR-M2-011-2 | 存储 `match_scheme_json` + `match_type` |
| FR-M2-011-3 | 保存时 Football 发布方案双写（失败不阻断 OPS 保存） |

| FR-M2-011-5 | 任务预填 N 场赛程，不预填玩法 |

### 13.4 AI 排版与一键排版（FR-M2-012）

| 子需求 | 要点 |
|--------|------|

| FR-M2-012-3 | 正文保真：排版前后纯文本一致 |
| FR-M2-012-4 | 预览后确认应用 |
| FR-M2-012-7 | 一键排版四套 FOOTBALL_AI 预设（无 LLM） |

**双路径铁律**：文案 jingcai；排版 M8 LLM 或规则预设；二者不互相 fallback。

## 14. 核心业务规则索引（BR-001 ~ BR-024）

| 编号 | 名称 | 摘要 |
|------|------|------|
| BR-001 | ROI 计算 | ROI = 总营收 ÷ 总成本 |
| BR-002 | 粉丝 LTV | 平均（取消关注时间 − 关注时间） |
| BR-003 | 爆款判定 | 阅读/点赞/评论/转发同时 ≥ 阈值（AND） |
| BR-004 | 低分判定 | 四维同时 ≤ 阈值（AND） |
| BR-005 | 三级审核 | 初审→复审→终审；任一驳回须修改重提 |
| BR-006 | 数据权限 | 角色 + 部门 + IP 组 + 人员四级 |
| BR-007 | 大屏数据 | 进入加载，不自动轮询，可手动刷新 |
| BR-008 | SOP 并行 | 同并行组可同时推进；汇聚节点等待全部前置 |
| BR-009 | 审核状态机 | 驳回回到执行中重新提交 |
| BR-010 | 绩效自动算分 | 指标引擎 + 模板权重；支持人工微调 |
| BR-011 | 财务审计 | 成本修改记录操作人与时间 |
| BR-012 ~ BR-018 | 报表与预警 | 八张标准报表字段与账号异常预警规则 |
| BR-019 | IP 组层级 | 大组管小组；大组不直接管账号/主播 |
| BR-020 | 运营→主播 | 一对多关联，按 IP 组归类 |
| BR-021 | 成本明细 | 购买成本一次性；过程成本多条 |
| BR-022 | 公众号容量 | 剩余可注册低于阈值预警 |
| BR-023 | 三方关联 | 微信 + 视频号 + 企微绑定统计 |
| BR-024 | 自定义查询发布 | 管理员发布查询供他人直接使用 |
