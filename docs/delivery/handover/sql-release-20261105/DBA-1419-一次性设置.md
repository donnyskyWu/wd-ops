# MySQL Error 1419 · 一次性 DBA 设置（投产比 handover）

## 现象

导入 `shenyu-ops-full.sql` / `shenyu-ops-routines.sql` 时出现：

```text
ERROR 1419 (HY000): You do not have the SUPER privilege and binary logging is
enabled (you *might* want to use the less safe log_bin_trust_function_creators variable)
```

常见环境：`log_bin = ON`，`log_bin_trust_function_creators = OFF`，业务/运维账号**无 SUPER**。

**无法**通过修改 handover SQL 内容绕过；必须在实例级打开 `log_bin_trust_function_creators`。

---

## 运维推荐路径（无 SUPER）

1. 先导入 **`shenyu-ops-schema.sql`**（表结构 + 种子，不触发 1419）。
2. 把本文发给 DBA，完成下面「一次性设置」并**校验通过**。
3. 再导入 **`shenyu-ops-routines.sql`**（审计函数/触发器 + Section 03 费用列扩展）。
4. 导入 **`shenyu-system.sql`**（与 ops 顺序：ops schema → ops routines → system，或 routines 与 system 在 schema 之后均可，system 独立库）。

若 DBA **已**开 trust，可跳过 1+3，直接一次导入 **`shenyu-ops-full.sql`**（与 `shenyu-ops.sql` 相同）。

---

## DBA：一次性设置

### 1. 会话级（需 SUPER 或云厂商允许的 GLOBAL 权限）

```sql
SET GLOBAL log_bin_trust_function_creators = 1;
```

> 托管 RDS 上业务账号通常**不能**执行；请用控制台参数组或高权限账号。

### 2. 自建 MySQL 5.7 / 8.0 持久化

编辑 `my.cnf` / `mysqld.cnf`：

```ini
[mysqld]
log_bin_trust_function_creators = 1
```

保存后 **重启 mysqld**。

### 3. 阿里云 RDS / PolarDB MySQL

1. 登录 **RDS 控制台** → 目标实例 → **参数设置**（或 **参数模板 / 参数组**）。
2. 搜索参数 **`log_bin_trust_function_creators`**。
3. 将值改为 **`ON`** 或 **`1`**（以控制台可选值为准）。
4. **保存** → 按提示 **重启实例**（修改此类参数通常需重启才生效）。
5. 重启完成后，用只读账号执行下方「校验」。

### 4. 腾讯云 CDB / 其他云 MySQL

1. 控制台 → 实例 → **参数设置 / 参数模板**。
2. 找到 **`log_bin_trust_function_creators`** → 设为 **`1` / ON**。
3. **应用并重启实例**（与阿里云类似，勿仅依赖临时 SET GLOBAL）。

---

## 校验（任意有 SHOW VARIABLES 权限的账号）

```sql
SHOW VARIABLES LIKE 'log_bin_trust_function_creators';
-- 期望：Value = ON 或 1

SHOW VARIABLES LIKE 'log_bin';
-- log_bin = ON 时，更必须 trust = ON
```

---

## trust 已开之后执行什么

| 目标 | 命令示例 |
|------|----------|
| 仅补例程/触发器 | `mysql -hHOST -uUSER -p shenyu-ops < shenyu-ops-routines.sql` |
| 整包 ops（含例程） | `mysql -hHOST -uUSER -p shenyu-ops < shenyu-ops-full.sql` |
| system 库 | `mysql -hHOST -uUSER -p shenyu-system < shenyu-system.sql` |

## 安全说明（简要）

该选项允许非 SUPER 用户创建会被复制信任的存储函数。本 release 中 ROI 审计函数为 **`DETERMINISTIC NO SQL`** 投影函数，由 DBA 评估后开启。替代方案为授予 SUPER（生产通常不推荐）。

更多背景见同目录 `00-mysql57-prerequisites.sql`、`README.md`。
