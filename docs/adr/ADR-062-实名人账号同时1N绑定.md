# ADR-062：实名人 ↔ 平台账号同时 1:N 绑定

| 字段 | 值 |
|------|---|
| 状态 | **Accepted** |
| 日期 | **2026-08-01** |
| 关联 | API-M4 §5.2 · GLOBAL-CONVENTIONS §3.2 · CHECKLIST-M4 §3.3/§10 · ADR-M4 系列 |
| 触发 | 产品授权（2026-08-01 会话）：平台账号新增/编辑时，**一个实名人可同时关联多个账号** |

## 1. 背景

旧 Spec（API-M4 / CHECKLIST-M4）将实名人与账号按**独占绑定**处理：

- 已绑定到其他账号的实名人默认不可选（FE `exclude-bound`）
- 后端 `resolveBindingConflicts` 对 `realnameId` 抛 1502，需 `forceReplace=true` + `reason` 才能抢占并解绑原账号

运营诉求：同一实名人可同时挂多个平台账号（并发 1:N），无需强制替换。

DB 侧 `oa_account.realname_id` / `oa_account_ext.realname_id` **本无唯一约束**（仅非唯一索引或无索引），与 1:N 一致；阻塞在应用层独占校验与选择器过滤。

## 2. 决策（产品授权 · locked）

| # | 决策 |
|---|------|
| Q1 | 实名人 : 账号 = **同时 1:N**（一实名人可绑多账号；一账号仍至多一实名人） |
| Q2 | **取消**「已绑定实名人不可再选」独占语义；FE `RealNameSelect` 不再默认 `exclude-bound` |
| Q3 | BE `resolveBindingConflicts` **跳过** `realnameId`；不再因实名人已被他账号引用而返回 1502 |
| Q4 | `forceReplace` **保留**，仅用于手机 / 手机卡等仍独占的资源冲突；实名人路径不再依赖 forceReplace |
| Q5 | 手机 / 手机卡独占与 1502 / forceReplace **不变**（本 ADR 不放宽） |
| Q6 | 代码范围：`football-module-ops` + `football-front`；shenyu-ops 表结构不改 |
| Q7 | `account_bound_count` 仍按绑定/解绑增减，可 > 1 |

### 2.1 与旧 Spec 的关系

| 旧条款 | 本 ADR |
|--------|--------|
| API-M4「已绑定到其他账号的**实名人**/手机/手机卡」默认不可选 + forceReplace | **实名人**豁免；手机/手机卡条款仍有效 |
| CHECKLIST-M4「已绑定实名人 → 强制替换确认框」 | 废止；改为允许直接多绑 |
| GLOBAL-CONVENTIONS §3.2「已绑定…实名人…需强制替换」 | 实名人改为允许并发绑定；手机/卡不变 |

## 3. 行为

1. 账号 A 已绑实名人 X → 新建/编辑账号 B 选择同一 X → **成功**，无需 `forceReplace`。
2. A、B 同时保留 `realname_id = X`；X 的 `account_bound_count` 反映关联账号数。
3. 若同时冲突的是已占用手机/卡 → 仍 1502，FE 可走原 forceReplace UX。
4. 停用实名人（1501）、跨租户（1504）校验不变。

## 4. 非目标

- 不改手机 / 手机卡独占
- 不引入 DB 唯一索引或反向唯一约束
- 不删除 API 字段 `forceReplace` / `reason`（兼容其他资源）
