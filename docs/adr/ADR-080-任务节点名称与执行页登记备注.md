## 1. 背景

工作任务登记 confirm 后，「我的任务 / 全部任务 / 执行页」的 **节点名称** 被写成登记行 **营销计划** 字典标签，而不是 SOP 节点 `oa_sop_node.node_name`。根因：列表/执行 VO 对 `work_task_assignment_id` 非空的 task 走 `WorkTaskTaskBuilderSupport.resolveDisplayNodeName(marketingPlanLabel, sopNodeName)`，**优先返回营销计划**。

`oa_task.plan_name` 已按 ADR-077 D5 拼接「工作日 + 作者 + 赛事摘要 + **节点名**」；UI「任务名称」=`planName`，「节点名称」=`nodeName`。问题在 **nodeName 映射**，不改 plan_name 格式。

产品同时要求执行页（P-M2-012）：

- **不展示 SLA**
- **只读展示** 登记行：营销计划、是否直播、直播时间（仅是否直播=是）、销售平台

这些字段已在 `oa_work_task_assignment`（ADR-074），**未**拷贝到 `oa_task`。

---

## 2. 决策（Accepted）

| # | 决策 |
|---|------|
| **D1** | 列表 `TaskVO.nodeName` 与执行 `TaskExecuteVO.nodeName` **一律** = `oa_sop_node.node_name`（按 `oa_task.node_id`）。工作任务来源 **不得**用营销计划标签覆盖。无节点则空。 |
| **D2** | `oa_task.plan_name` **维持** ADR-077 D5（含 SOP 节点名）。不新增命名方案。 |
| **D3** | 执行页 **隐藏 SLA**（不展示 `slaDeadline` / slaHours）。列表 SLA 列 **不动**。VO 可保留 `slaDeadline` 字段。 |
| **D4** | 执行页增加 **登记备注**（只读）。有 `oa_task.work_task_assignment_id` 时 **read-through** 登记行，**不** denormalize 到 `oa_task`。计划管理生成的 task（无 assignment）**不**展示该区。 |
| **D5** | 执行页「备注」SSOT 字符串 `workTaskRemark`：每条关联登记行（含 ADR-075 合并组）一段 `赛事-营销计划-是否直播（直播时间）-销售平台；`。是否直播=是/否；直播时间仅 `isLive=1` 时写成 `是（HH:mm）`；营销计划/销售平台用字典**标签**。原四字段仍 read-through。 |
| **D6** | **不改** ADR-079 完成门禁。 |

---

## 3. API

`GET /ops/task/{id}/execute` 的 `TaskExecuteVO` 增加（均可空）：

| 字段 | 类型 | 说明 |
|------|------|------|
| marketingPlan | string | 登记行 `marketing_plan`（首行；UI 备注不用此字段） |
| isLive | int | 登记行 `is_live` |
| liveTime | time | 登记行 `live_time` |
| salesPlatform | string | 登记行 `sales_platform`（逗号分隔） |
| workTaskRemark | string | 每场一段 `赛事-营销计划标签-是/否（HH:mm）-销售平台标签；` |

`GET /task/list` · `/my-tasks` 的 `nodeName` 按 D1；**不**在列表增加备注字段。

---

## 4. UX

P-M2-012 基本信息：任务名称、节点名称、IP 组、赛事、状态；**去掉 SLA**。工作任务来源时同区仅一行「备注」：`赛事-营销计划-是否直播（直播时间）-销售平台；`（合并组多场多段；直播时间仅「是」时附在是否直播后；字典标签）。
