## 1. 背景

现行实现：

- 执行页 `POST /ops/task/{id}/execute/complete` 对 `CONTENT_GENERATION` 仅要求关联内容 **非 DRAFT / 非 REJECTED**（已提交即可完成）。
- 列表 `POST /ops/task/{id}/complete` **未**走同一门禁，且不校验工作说明。
- 内容模块「提交审核」仅 `DRAFT` / `REJECTED`；末级审核通过后内容进入 `PENDING_PUBLISH`（ADR-022），**无** `dict_content_status=APPROVED`。

产品确认两条规则（列表与执行页同一后端校验）：

1. `node_type ≠ CONTENT_GENERATION`：点「完成」必须填写 **工作说明**。
2. `node_type = CONTENT_GENERATION`：关联内容处于 **可提交审核** 时展示「提交审核」（效果同内容模块）；「完成」仅当关联内容 **审核通过**。

---

## 2. 决策（Accepted）

| # | 决策 |
|---|------|
| **D1** | **工作说明**字段 = 已有 `oa_task.deliverables`（API `deliverables`）。**不**新增列。UI 文案「工作说明」。 |
| **D2** | `node_type ≠ CONTENT_GENERATION`（含 `NORMAL` / `CONTENT_PUBLISH`）：`complete` 与 `execute/complete` 均要求 `deliverables` trim 后非空，否则 **1500**「请填写工作说明」。 |
| **D3** | `node_type = CONTENT_GENERATION`：**完成**须存在 `oa_content.task_id=当前任务`（租户内）且内容状态属于 **审核通过**集合（§3）。否则 **1500**（无记录：「须先关联内容记录」；有记录未通过：「内容须审核通过后方可完成任务」）。完成 **不**要求工作说明。 |
| **D4** | **可提交审核** = 内容模块同一条件：`DRAFT` \| `REJECTED`（`ProductionContentServiceImpl.isSubmittableStatus` / 内容列表「提交审核」）。动作 = `POST /ops/content/{id}/submit-review`，**不是**任务级 `POST /ops/task/{id}/submit-review`。 |
| **D5** | 列表与执行页 **同一** Service 校验；禁止只在执行页校验。`POST /ops/task/{id}/submit-review`（SOP `need_review=1`）走同一完成门禁，避免列表旁路。 |
| **D6** | 列表 `TaskVO` 增加 `nodeType` + `linkedContent`（至少 `id` / `status`），供按钮显隐。 |
| **D7** | `execute/complete` 请求体与 `complete` 对齐：可选 `deliverables`（执行页可先 save 再 complete；后端以本次 body 非空为准，否则用已存 `oa_task.deliverables`）。 |
| **D8** | **不**改 ADR-077 jingcai / 自动草稿 / AI Job；自动草稿仍 `DRAFT` 且 **不**标任务完成。本 ADR 只收紧人工「完成」门禁。 |
| **D9** | 错误码走 **1500** 段（铁律）；历史文档 **2008**「须先完成内容创作」由本门禁取代，实现不再抛 2008。 |
| **D10** | SOP `need_review=1` 时，「完成」成功后任务仍 → `PENDING_REVIEW`（既有）。`CONTENT_GENERATION` 在内容可提交时按钮文案为内容「提交审核」；内容已审核通过后按钮为「完成」（即使随后进入任务级待审核）。 |

## 3. 状态码（SSOT）

`dict_content_status`。**无**内容态 `APPROVED`；「审核通过」= 末级审核已通过及之后（ADR-022 `PENDING_PUBLISH` 起）。

| 产品语义 | 字典 value | 说明 |
|----------|-----------|------|
| **可提交审核** | `DRAFT`、`REJECTED` | 与内容列表 / `submit-review` 一致 |
| **审核通过**（允许完成任务） | `PENDING_PUBLISH`、`PUBLISHED_DRAFT`、`FORMALLY_PUBLISHED`、`PUBLISHED`、`UNPUBLISHED` | 待发布及发布后；**不含** `COMPLETED`（ADR-016 遗留「确认」态，须再走提交审核） |
| **不可完成、也不可提交** | `PENDING_FIRST_REVIEW`、`PENDING_SECOND_REVIEW`、`PENDING_FINAL_REVIEW`、`COMPLETED` | 审核中或遗留确认态 |

实现复用 `ContentStatusSupport.isReviewApproved` / `isSubmittable`；**不**把 `COMPLETED` 算进 `isReviewApproved`（上架 `isReviewApprovedForShelf` 仍可含 `COMPLETED`，本 ADR **不改**上架规则）。

## 5. UX

- **执行页 / 列表** 非内容生成：完成前须工作说明（执行页已有「工作说明」区；列表弹窗必填）。
- **内容生成**：关联内容 `DRAFT`/`REJECTED` →「提交审核」；`PENDING_*` → 完成禁用；审核通过集合 →「完成」可用。
- 文案与后端 1500 消息一致。
