# 语义解析引擎（两模板共用）

## 元素类型与正则匹配

| 元素 | 正则匹配 | HTML 标签 | 说明 |
|------|---------|----------|------|
| 文章标题 | 首行或 `^#\s+.+` 或文章最开头的独立短句 | `<h1>` | 通常文章第一行，长度 < 30 字 |
| 比赛头 | `^(周[一二三四五六日])\s*\d+\s+(.+)$` | `<h2>` | 如"周日215 挪超" |
| 对阵行 | `^(.+?)\s*[Vv][Ss]\s*(.+)$` | `<p>` | 如"桑纳菲尤尔 VS 博德闪耀"，18px 粗体居中 |
| 比赛时间 | `^比赛时间[：:]` | `<dd>`（内嵌于 `<dl>`） | 固定前缀格式，用定义列表包裹 |
| 比赛元数据 | 联赛/时间/状态等键值对 | `<dl>`+`<dt>`+`<dd>` | 多组元数据水平排列 |
| 分析段落 | 非以上类型的普通文本 | `<p>` | 多行可能构成一个段落 |
| 小标题 | 以"："结尾且长度 < 20 字的行 | `<h3>` | 如"基本面分析："、"数据面分析：" |
| 推荐列表 | `^(竞彩推荐|比分推荐|指数推荐)[：:]` | `<ul><li>` | 固定三行格式 |
| 图片占位符 | `【这里插入.+图】` | `<p>` | 居中灰色显示 |
| 分割线 | `^-{3,}$` 或 `^\*{3,}$` | `<hr>` | `— — —` 风格 |
| 免责声明 | 包含"免责"、"声明"、"仅供"、"参考"的行 | `<p>`+`<small>` | 放最后，浅灰色 |
| 引用语 | 带引号或"「」"的短句 | `<blockquote>`+`<footer>` | 带来源标注 |
| 引用来源 | "—— 作者名" 位于引用后 | `<footer>` | 独立一行放引用后面 |
| $N$ 个递进句 | "一场…一组…"结构 | `<ol>`+`<li>` | 有序列表 |
| 装饰标语 | "这个就叫专业" + 英文 | `<figure>`+`<figcaption>` | 居中，左右穿越线 |

## 语义解析算法

```
Step 0: 先全局扫描原文，生成"语义识别清单"
        识别内容块类型，判断每个内容块的组件选择是否合理

Step 1: 按换行分割文本为行数组
Step 2: 第一行若长度 < 30 → 识别为文章标题
Step 3: 逐行匹配元素类型
Step 4: 连续的分析段落行合并为一个段落（除非被空行隔开）
Step 5: 推荐列表的三行（竞彩推荐/比分推荐/指数推荐）连续相邻时 → 组合为 <ul> 列表
Step 6: 识别图片占位符的类型
Step 7: 对每个分析段落 `<p>` 应用段内语义高亮规则
Step 8: 根据原文语义选择正确的 HTML 组件
```

**关键验证：** Step 0 完成后自查组件选择正确性。

## 图片占位符类型识别

当文本中包含"【这里插入...图】"时，按关键词表匹配。

```
匹配算法：
  对每种图片类型的 keywords 列表，统计周围段落中出现的数量
  → 命中最多者 = 图片类型
  → 若命中数并列 → 选优先级高的（表中序号小）
  → 若全部 0 命中 → 默认"赛前情报图"
```

| # | 图片类型 | 关键词 | 占位符文本 |
|--:|---------|-------|-----------|
| 1 | 赛前情报 | 近期战、状态、近N场、伤停、阵容、首发、平均年龄、身价、伤病名单、停赛、球员缺席 | 【这里插入赛前情报图】 |
| 2 | 数据分析 | 指数、数据、统计、概率、胜负概率、胜率、期望值、xG、expected、控球率、射门数、传球成功率 | 【这里插入数据分析图】 |
| 3 | 历史交锋 | 交锋、历史战、此前交手、H2H、交手记录、对决、往绩、对战、对赛、交战 | 【这里插入历史交锋图】 |
| 4 | 积分榜 | 排名、积分、联赛榜、积分榜、排第、榜首、榜尾、领先、落后、保级、争冠 | 【这里插入积分榜图】 |
| 5 | 即时指数 | 赔率、盘口、亚指、欧指、即时赔、指数变化、水位、升降、凯利、返还率 | 【这里插入即时指数图】 |
| 6 | 伤停 | 伤病、受伤、缺阵、缺席、伤缺、恢复训练、复出、出战成疑 | 【这里插入伤停图】 |
| 7 | 战术分析 | 阵型、打法、战术、部署、4-3-3、4-4-2、3-5-2、防反、控球、高位逼抢、防守反击 | 【这里插入战术分析图】 |

若原文已是"【这里插入 xx 图】"格式，直接保留。若无图片占位符，不自动插入。

## 推荐列表解析

推荐列表固定为三行，解析为 `<ul>` 列表：

```
竞彩推荐：负                  → 标签=竞彩推荐 值=负
比分推荐：0-2、0-3           → 标签=比分推荐 值=0-2、0-3
指数推荐：博德闪耀 -1.5      → 标签=指数推荐 值=博德闪耀 -1.5
```

推荐列表的具体渲染格式由所选模板的组件库定义（见 `template-*.md` 的推荐组件规则）。

## 段内语义高亮规则

> 正文段落必须通过差异化排版增强可读性。每个模板可以自定义具体颜色，但高亮优先级逻辑通用。

**高亮匹配规则（按优先级从上到下）：**

| 优先级 | 语义类型 | 匹配模式 | 高亮方式 | 示例 |
|--------|---------|---------|---------|------|
| 1 | 项目/品牌名 | `【[^】]+】` | 加粗+主色 | **【战无不胜】** |
| 2 | 核心概念 | 单关、二串一、稳胆、赔率、指数 | 加粗+主色 | **单关** |
| 3 | 数字比分 | `\d+[-:]\d+` | 加粗+强调色+高亮背景 | **0-2** |
| 4 | 胜负关键字 | `(胜\|负\|平)` 独立成词 | 强调色+高亮背景 | **负** |
| 5 | 推荐信号词 | 推荐、关注、看好、注意 | 加粗+强调色 | **推荐** |
| 6 | 对比结构 | 防守、进攻、守、攻 | 防守=主色 进攻=强调色 | **防守线** vs **进攻线** |
| 7 | 球队名 | 2-6字中文队名 | 加粗+强调色 | **博德闪耀** |
| 8 | 并列排比 | "一边…一边…"等对比句式 | 高亮背景+加粗 | **一边防守一边进攻** |
| 9 | 结论/总结句 | 段落结尾的总结性短句 | 加粗+强调色 | **这才是真正意义** |

**匹配算法：** 按优先级从上到下遍历，匹配到就用对应 `span` 包裹，已被包裹的文本不再参与后续匹配。

**约束：** 高亮密度 ≤ 段落 30%，同类型高亮 ≤ 3 处/段。禁止全段同色。具体颜色值由当前模板决定。

## 结构视觉区隔规则

> 核心概念块使用背景卡片增强扫读。每个模板定义自己的卡片类型表。以下为通用规则：

- 每篇文章至少使用 2 种卡片类型
- **推荐结果卡片为强制使用类型**（只要文章包含推荐列表就必用此卡片）
- 所有可见标签的内联 style 中独立包含完整 font-family 字体栈
