# football-layout — 足球分析文章排版引擎

## 目录结构

```
football-layout/
├── SKILL.md                         # 本文件：入口 + 工作流
├── template-decision-scan.md        # 模板：决策扫读版（默认）
├── template-analysis-report.md      # 模板：情报分析版
└── shared/
    ├── semantic-parser.md           # 语义解析引擎（两模板共用）
    └── params.md                    # 排版参数 + NL 调整（两模板共用）
```

## 模板选择 — 强制选择

> **必须让用户选择模板，无默认值。** 用户在输入文章原文后，必须同时指定模板。若未指定，必须输出引导语要求用户二选一。

| 用户输入 | 目标模板 | 说明 |
|---------|---------|------|
| 决策扫读版、扫读版、精简版、模板一 | `template-decision-scan.md` | 所有样式内联，复制到编辑器保留格式 |
| 情报分析版、分析版、报告版、深度版、模板二、阿豹料码版 | `template-analysis-report.md` | 品牌感+数据可视化，所有样式同样内联，复制到编辑器保留格式 |

**强制选择逻辑：**
```
IF 用户输入包含模板选择词 → 加载对应 template-*.md
ELSE IF 用户输入包含文章原文但无模板选择词 → 输出引导语："请选择排版模板：① 决策扫读版 ② 情报分析版（两模板均内联，复制到编辑器保留格式）"
ELSE → 按首次使用引导处理
```

## 首次使用引导

**当用户触发本 skill 且未直接提供文章时：**

```
你好！请把你的足球分析文章原文发给我，我来帮你排版成适配手机端的精美 HTML。

但在开始之前，你需要选择一个排版模板（二选一）：

① **决策扫读版** — 620px容器，红边框预测卡片，公众号编辑器友好。复制到编辑器保留格式。
② **情报分析版** — 720px容器，渐变头部+统计条+赔率表+对阵卡，品牌感强。复制到编辑器保留格式。

请告诉我用哪个模板，然后把文章原文一起发来。
```

若用户直接提供文章原文且已指定模板（原文中包含模板选择词），跳过引导语，直接进入 Step 0。

若用户仅提供文章原文但未指定模板 → 输出模板选择引导语要求二选一（同 line 51-52 逻辑）。

若用户提供的是图片/截图 → 提示"请提供文章的文字内容，我需要原文才能排版"。

## 工作流程

### Step 0：模板选择 + 原文语义识别

```
1. 检查用户输入中是否有模板选择词 → 确定当前模板
   （无默认值，用户必须指定模板）
2. 扫描全文，生成"语义识别清单"
   - 识别内容块类型：赛事档案 / 基本面分析 / 数据统计 / 战术分析 / 赔率解读 / 推荐预测
   - 判断每个内容块在选定模板下应使用的组件
3. 输出识别清单后进入 Step 1
```

**关键验证：** 组件选择是否准确匹配原文语义 + 选定模板的组件库（见 `template-*.md` 的组件选择逻辑）。

### Step 1：语义解析

按 `shared/semantic-parser.md` 的解析规则逐行解析：
- 按换行分割文本
- 逐行匹配元素类型
- 合并连续分析段落
- 组合推荐列表
- 识别图片占位符

### Step 2：应用排版参数

使用当前模板的默认参数值（见 `template-*.md` 的排版参数表）。
若之前有用户调整记录，使用调整后的参数。

### Step 3：生成 HTML

根据模板选择，使用 `template-*.md` 中的 HTML 模板和组件渲染规则生成：

1. 填充 HTML 模板结构（固定标题栏、文章容器、复制脚本、Toast）
2. 按语义解析结果逐元素填充内容
3. 应用段内高亮规则（颜色值按当前模板）
4. 应用卡片区隔（按当前模板的卡片类型表）

**关键填充逻辑：**
- 文章标题同时填入 `<title>`、`#toolbar-title` 和内容区标题
- 无标题时 toolbar-title 显示"足球分析文章"
- 所有可读文本颜色 ≥ #888898（法律文本 ≥ #b0b0c0）
- 段落内混合 ≥2 种视觉增强手段

**生成后强制验证：** 必须包含：
1. `id="copy-btn"` 的按钮（带 `onclick="copyFormatted()"`）
2. `<script>` 内的 `copyFormatted()` 函数
3. `id="toast"` 的 Toast 元素

### Step 4：反馈

向用户反馈：
- 文件名和路径
- 使用的模板名称
- 识别到的结构概览（标题、章节数、段落数、推荐列表数、图片数）
- 提示可用自然语言调整

```
排版已生成（模板：{模板名}，移动端适配）。如需调整：
  ▸ 改颜色/字号： "标题深蓝" "正文改成16px"
  ▸ 调间距： "间距加大" "紧凑一些"
  ▸ 切换模板： "切换到情报分析版" "换回决策扫读版"
  ▸ 改主题色： "主题色改成绿色"
  ▸ 恢复默认： "恢复默认"
  ▸ 查看全部可调参数： "帮我看看可以调什么"
```

### Step 5：自然语言调整

按 `shared/params.md` 的 NL 映射规则处理用户调整要求：

1. 解析 NL → 按匹配模式表逐级匹配
2. 检查是否为模板切换请求
3. 若匹配失败 → 按失败处理协议响应
4. 若含多命令 → 拆分为原子操作依次执行
5. 更新参数表（或切换模板）
6. 重新生成 HTML
7. 反馈调整结果（告知变了什么，旧值→新值）

- [ ] 文章标题正确渲染
- [ ] 正文 ≥ 14px、行高 ≥ 1.8
- [ ] 最小字号 ≥ 14px（特殊场景 13px 为极限）
- [ ] 所有可读文本颜色 ≥ #888898（法律文本 ≥ #b0b0c0）
- [ ] 每个段落混合 ≥2 种视觉增强
- [ ] 推荐列表正确渲染为指定卡片
- [ ] 引用块使用 `<blockquote>`
- [ ] 元数据使用 `<dl>`+`<dt>`+`<dd>`

- [ ] 章节间有分割或间距区分
